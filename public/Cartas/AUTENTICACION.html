Guía de integración — métodos Hash Token y JWT Bearer

Hash Token (Legacy) JWT Bearer
Test

Resumen

La API expone dos mecanismos de autenticación. Ambos protegen los mismos datos de ubicación pero a través de controladores y flujos distintos.

Característica Hash Token (Legacy) JWT Bearer
Tipo de token Hash hexadecimal (40 chars) JWT firmado HS256
Método de login GET con header Credentials POST con body JSON
Header en consultas Token: <hash> Authorization: Bearer <jwt>
Controlador de datos /Ubicacion /UbicacionJwt
Swagger Integrity Helpers Helpers JWT

Método 1 — Hash Token (Legacy)

Flujo

Credenciales
en Base64
usuario|clave → base64
→
GET /autenticar
Credentials header
Paso 1
→
Hash Token
Respuesta
→
GET /Ubicacion/*
Token header
Paso 2
1
Obtener token — codificar credenciales y autenticar

Concatenar usuario y clave con el separador |, luego codificar el resultado en Base64. 

# Codificación
"usuario|clave"  →  Base64  →  dXN1YXJpb3xjbGF2ZQ==
GET https://tyd.integrityseguros.com.ar:4434/helpers/autenticar
Accept:       text/plain
Credentials: dXN1YXJpb3xjbGF2ZQ==
Response 200 OK
A35BA03C9CF94ECE8B2EA11D190E82949484354D
Nota: el token es un hash hexadecimal de 40 caracteres. Almacenarlo para usar en el siguiente paso.
2
Consultar endpoint — enviar token en header

Incluir el hash obtenido en el header Token de cada request.

GET https://tyd.integrityseguros.com.ar:4434/general/helpers/Ubicacion/Provincias/bue
Accept: application/json
Token:  A35BA03C9CF94ECE8B2EA11D190E82949484354D
Response 200 OK
{
  "01": "Buenos Aires",
  "21": "Ciudad de Buenos Aires"
}

Ejemplo cURL completo

# Paso 1 — autenticar
curl -X GET "https://tyd.integrityseguros.com.ar:4434/helpers/autenticar" \
     -H "Credentials: dXN1YXJpb3xjbGF2ZQ=="

# Paso 2 — consultar con el token recibido
curl -X GET "https://tyd.integrityseguros.com.ar:4434/general/helpers/Ubicacion/Provincias/bue" \
     -H "Token: A35BA03C9CF94ECE8B2EA11D190E82949484354D"

Método 2 — JWT Bearer

Flujo

POST /GenerarToken
{ user, pass }
Paso 1
→
JWT Token
{ token: "eyJ..." }
Respuesta
→
GET /UbicacionJwt/*
Authorization: Bearer
Paso 2
1
Obtener token JWT — POST con credenciales en body JSON

Enviar usuario y contraseña en el body del request en formato JSON.

POST https://tyd.integrityseguros.com.ar:4434/general/helpers/SeguridadJwt/GenerarToken
Content-Type: application/json
Accept:       application/json

{
  "UserName": "user",
  "Password": "pass"
}
Response 200 OK
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzaWQiOiIxNDI3N..."
}
Response 401 Unauthorized — credenciales inválidas
{ "error": "Credenciales inválidas." }
Expiración: el JWT tiene validez limitada (por defecto 30 minutos). Al recibir 401 en una consulta, repetir este paso para obtener un nuevo token.
2
Consultar endpoint protegido — enviar JWT en header Authorization

Incluir el JWT en el header Authorization con el prefijo Bearer seguido de un espacio. 

GET https://tyd.integrityseguros.com.ar:4434/general/helpers/UbicacionJwt/Provincias/bue
Accept:        application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzaWQiOiIx...
Response 200 OK
{
  "01": "Buenos Aires",
  "21": "Ciudad de Buenos Aires"
}
Response 401 Unauthorized — token inválido o expirado
{ "error": "Unauthorized" }

Ejemplo cURL completo

# Paso 1 — obtener JWT
curl -X POST "https://tyd.integrityseguros.com.ar:4434/general/helpers/SeguridadJwt/GenerarToken" \
     -H "Content-Type: application/json" \
     -d '{"UserName":"user","Password":"pass"}'

# Paso 2 — consultar con Bearer token
curl -X GET "https://tyd.integrityseguros.com.ar:4434/general/helpers/UbicacionJwt/Provincias/bue" \
     -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
