Estructura del token JWT

El token sigue el estándar RFC 7519. Está compuesto por tres segmentos en Base64URL separados por puntos:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
Header
.
eyJzaWQiOiIxNDI3NTk5MTciLCJzeXMiOiIyMDkxIiwi...
Payload (claims)
.
psOYFvsrF2pfHLhPVGi5bF0NZFwD2UkQZvucnh1ZEcI
Signature

Header

El header declara el algoritmo de firma y el tipo de token. Decodificado en Base64URL:

{
  "alg": "HS256",  // algoritmo: HMAC SHA-256
  "typ": "JWT"    // tipo: JSON Web Token
}

Algoritmo y clave de firma

Algoritmo

HS256
→
HMAC con SHA-256 — firma simétrica (misma clave para firmar y validar)

Tipo de clave

Importante

La clave es simétrica (shared secret): la misma clave se usa tanto para generar el token (en el endpoint de login) como para validarlo (en cada request protegido).


Encoding de la clave UTF-8
Longitud mínima recomendada 256 bits (32 caracteres)
Origen Configuración interna de la aplicación (no expuesta en el token)

Proceso de firma

// Pseudocódigo de generación
keyBytes     = UTF8.GetBytes(secretKey)
signingKey   = new SymmetricSecurityKey(keyBytes)
credentials  = new SigningCredentials(signingKey, "HS256")
token        = JwtSecurityTokenHandler.CreateToken(descriptor)

Proceso de validación

// Lo que valida la aplicación en cada request
TokenValidationParameters {
  ValidateIssuerSigningKey: true,   // verifica la firma con la clave secreta
  IssuerSigningKey:         SymmetricKey(UTF8(secretKey)),
  ValidateIssuer:          false,  // no valida el campo "iss"
  ValidateAudience:        false   // no valida el campo "aud"
}
Para API Gateway

El gateway debe validar el token usando la misma clave secreta con el algoritmo HS256. No es necesario validar iss ni aud. Solo se requiere verificar:

  • Firma válida (clave correcta)
  • Token no expirado (exp > now)

Claims del Payload

Token decodificado — ejemplo real:

{
  "sid":         "142759917",    // ID de sesión Integrity
  "sys":         "2091",         // ID de sistema (fijo)
  "adm":         "true",         // es administrador
  "vds":         "true",         // puede ver datos sensibles
  "unique_name": "usuario",      // nombre de usuario (ClaimTypes.Name)
  "tkn":         "8338FE3C43D14F98811180A91C43FAD652A3D3C3F", // master token Integrity
  "nbf":         1779378234,    // not before (Unix timestamp)
  "exp":         1779380032,    // expiration (Unix timestamp)
  "iat":         1779378234     // issued at (Unix timestamp)
}

Descripción de cada claim

ClaimTipoDescripciónEjemplo
sid string ID numérico de la sesión en Integrity "142759917"
sys string Identificador del sistema. Valor fijo. "2091"
adm string Indica si el usuario tiene rol administrador "true" / "false"
vds string Indica si el usuario puede ver datos sensibles "true" / "false"
unique_name string Nombre de usuario. Equivale a ClaimTypes.Name del estándar .NET, serializado como unique_name en JWT. "jperez"
tkn string Master token del sistema de sesiones Integrity (hash hexadecimal). Para uso interno. "8338FE3C..."
nbf number Not Before — Unix timestamp desde el cual el token es válido 1779378234
exp number Expiration — Unix timestamp en que el token expira 1779380032
iat number Issued At — Unix timestamp de generación del token 1779378234

Expiración

Comportamiento
Campo exp (Unix timestamp UTC)
Duración por defecto 30 minutos desde la emisión
Cálculo exp = iat + (ExpirationInMinutes × 60)
Al expirar HTTP 401 Unauthorized — el cliente debe solicitar un nuevo token

Configuración para API Gateway

Parámetros necesarios para configurar la validación JWT en cualquier gateway compatible con HS256:

ParámetroValor
Algoritmo HS256 (HMAC SHA-256)
Tipo de clave Simétrica — shared secret
Encoding de la clave UTF-8
Validar Issuer (iss) No requerido
Validar Audience (aud) No requerido
Validar Firma Sí — obligatorio
Validar Expiración (exp) Sí — obligatorio
Header de entrada Authorization: Bearer <token>
Claim de identidad unique_name (usuario)
Seguridad — clave secreta

La clave secreta no debe transmitirse por ningún canal público ni incluirse en el token. Debe compartirse de forma segura entre el emisor del token (esta API) y el validador (API Gateway) fuera de banda. Rotar la clave invalida todos los tokens existentes.

Flujo técnico resumido

1. Cliente  →  POST /SeguridadJwt/GenerarToken  { UserName, Password }
2. API      →  valida credenciales contra sistema de autenticación Integrity
3. API      →  construye payload con claims (sid, sys, adm, vds, unique_name, tkn)
4. API      →  firma token:  HMAC-SHA256( base64(header) + "." + base64(payload), secretKey )
5. API      →  devuelve { "token": "eyJ..." }

──────────────────────────────────────────────────────────

6. Cliente  →  GET /UbicacionJwt/*   Authorization: Bearer eyJ...
7. Gateway  →  extrae token del header Authorization
8. Gateway  →  verifica firma con secretKey (UTF-8, HS256)
9. Gateway  →  verifica exp > now
10. Gateway →  permite o rechaza el request (200 / 401)
